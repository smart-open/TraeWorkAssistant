## 📋 1. 背景与现状

### 1.1 问题

自定义模型（custom 池）目前是「单上游直通」：

1. **同名不能多条**：`upsert` 强制 canonical 名称唯一，无法为同一模型配置多个上游（不同供应商 / 同供应商多 Key）做负载。
2. **无负载均衡**：单上游单 Key，无选路。
3. **无重试**：失败即错误直返。
4. **无熔断**：上游故障期间每请求都硬打已知故障的上游。
5. **无跨池回退**：自定义模型与 Trae/Buddy 同名时恒赢（⓪ 段短路），上游全挂时客户端直接 5xx，即使 Trae/Buddy 有同名模型可用。

## 🎯 2. 目标与非目标

### 2.1 目标

1. **按模型调度（同名多条）**：同一模型名可配置多条上游记录（不同 base_url / api_key），形成「上游组」；同名同 base_url 不同 api_key = 同上游多 Key 分摊限流，为天然支持场景。
2. **普通池语义（v3 拍板）**：custom **不再默认优先**——作为第五资源池参与统一调度规则（priority / per_model / Smart / Key 绑定 / fallback 全链路生效）；默认候选序中 custom 位于**尾部兜底**；纯 custom 模型（无同名 trae/buddy/qoder 源）为唯一源，天然直达不受序影响。
3. **显式指定通道（v3 拍板）**：① `custom/模型名` 前缀锁池直达（与其他池前缀同语义：单池候选、不可用显式报错不跨池回退）；② API Key 绑定池下拉扩为 **「全局 / Trae / Buddy / Qoder / 自定义」**——绑定 custom = custom 优先 + 不可用按序回退（「偏好非硬限制」，与其他绑定一致）；③ per_model 优先级数组可写 `"custom"` 任意位置。
4. **调度负载（主备 + 加权轮询）**：组内默认加权轮询；条目可标记 `standby` 备胎——平时全打活跃条目，活跃失败/全熔断才启用备胎（failover 主备语义，快速失败切换的目标形态）。
5. **请求均衡**：加权轮询按次数分摊；同会话粘同上游（保护上游侧 prompt cache）——粘性窗口内（60s）单会话不均衡是有意取舍，全局视角仍按权重分摊。
6. **快速失败切换**：组内重试——所选上游失败且未向客户端产出任何字节（`!sent_any`）时，换组内下一上游重试（连接超时收窄至 3s，见 §5.2）；`sent_any` 后就地收尾。
7. **熔断可自动恢复**：每条上游独立渐进冷却；故障上游退出选路，冷却过期自然放行（半开）——半开探测若失败，组内轮换立即兜底切换其他上游，客户端无感（见 §6.2）。
8. **跨池切换**：custom 组全熔断时按候选序回退下一池；多源同名模型 custom 默认兜底位参与 fallback 链；custom 恢复后按粘性/序回流。
9. **可观测**：每上游失败计数/冷却窗口/主备角色在池状态接口与 UI 可见；`custom/` 前缀与绑定 custom 的落池走现有 `[SCHED]` 行与 `dispatch fallback` 口径。

### 2.2 非目标（拒绝理由记录，防重复建议）

| 提案 | 结论 | 理由 |
|---|---|---|
| ~~`custom/xxx` 池前缀锁池~~ / ~~per_model 写 `"custom"`~~ | **已采纳（v3 转正）** | 用户拍板：`TargetPool::parse` 扩展 `"custom"` → `Some(Custom)`，前缀锁池与 per_model 写入随 parse 打通自然生效（§7.1） |
| 熔断状态持久化（落 SQLite） | 不做 | 重启清零即可，与池粘性（内存态不落盘）同口径；持久化收益低、复杂度高 |
| 后台主动探活线程 | 不做 | 半开语义由「冷却窗口到期后下一请求自然放行」保证，Qoder 已验证该模式够用；`custom_model_test` 保留为手动探活 |
| P2C / least-error 等高级负载策略 | 第一版不做 | 单进程内加权轮询 + 主备已满足；选路函数签名留位（`pick_upstream` 收敛为唯一入口），后续策略可插拔 |
| 竞速对冲（hedging，同请求并发多上游取先回） | 不做 | 复杂度高（双倍上游成本、双份用量记账、去重协调）；qoder_route 已有 hedge 实现可借鉴，若组内快速失败实测不满足延迟要求再立项 |
| 最少在途（least-inflight）/ EWMA 延迟感知动态权重 | 不做 | 需要每上游在途计数与延迟滑动窗口；加权轮询 + 熔断 + 主备已覆盖主要失衡场景（慢长流堆积由熔断兜底）。列为后续增强首选 |
| 组内点名单条上游（如 `glm-5.3#2`） | 不做 | 点名单条 = 用不同 name 配置；组内条目无独立路由键，引入选择器语法徒增复杂度 |
| 分布式/多实例负载 | 不做 | 桌面单进程应用 |

## 🔧 3. 总体设计

### 3.1 核心思路

> **不发明新机制，只做语义嫁接**：
> 同名多条 = 上游组；负载 = 组内选路（对齐账号池 pick 语义）；熔断 = 镜像 Qoder 渐进冷却（键从 model 换成 `cm.id`）；跨池切换 = 让 Custom 成为 `ModelSources` 第四源，复用 dispatch 现成 fallback 管线。

### 3.2 改造后请求走向

```
外部请求（custom 上游组 + trae/buddy 同名共存，v3 语义）
  ① 前缀锁池：trae/xxx / custom/xxx → 单池候选直达，不可用显式报错不回退
  ② 源集合收集：buddy + trae + qoder + custom(上游组) 四源并行判定
  ③ 候选序（统一调度规则，custom 为普通池）：
       默认        = [buddy, trae, qoder, custom]（priority 补全，custom 尾部兜底）
       per_model   = 用户显式数组（可含 "custom" 任意位置，校验放行）
       Key 绑定    = [绑定池, 其余补全]（绑定 custom → custom 优先）
       Smart 重排  = 四池参与（custom 键：无到期 → i64::MAX 后置，
                     倍率 → 组内最小 rate，无积分 → 后置）
  ④ pool_health(custom)：任一上游未熔断 → Ok → P2 组内选路 → 执行
       全熔断 → Err(no_healthy_account) → 现有 fallback 接管按序回退
       （纯 custom 单源模型：唯一源，无序可排直达 custom，全熔断 → 503）
  ⑤ 粘性：正常 record_sticky（含 Custom）；回退期间粘新池，TTL 60s 过期后回探
```

组内执行（P2/P3 细节见 §5/§6）：

```
组内未熔断上游按加权轮询选路
  ├─ 成功 → 返回
  ├─ 失败 && !sent_any → 排除已试，换组内下一上游（≤ min(N, 3) 轮）
  │    └─ 全部试完 → 失败直返（对齐 wb/qoder 轮换耗尽语义）
  └─ 失败 && sent_any → 就地收尾，不轮换（SSE 铁律）
```

### 3.3 分阶段总览

| 阶段 | 内容 | 独立可交付 |
|---|---|---|
| P1 | 数据模型：放开同名约束，多条 = 上游组 | 是（无行为变化，仅能力解锁） |
| P2 | 负载均衡：组内加权轮询 + 粘性 + 重试轮换 | 是（P1 后即可生效） |
| P3 | 熔断：实例级渐进冷却 + 全熔断错误矩阵 | 是（叠加在 P2 选路上） |
| P4 | 跨池整合：Custom 入源集合，复用 fallback | 是（前面全部完成后收口） |

## 🔧 4. P1 数据模型：同名多条 = 上游组

### 4.1 数据结构变更

`src-tauri/src/api_server/custom_models.rs`：

```rust
pub struct CustomModel {
    // ... 现有字段不变 ...
    /// 负载权重（默认 1；0 视为 1）——组内加权轮询用（P2 生效）
    #[serde(default = "default_weight")]
    pub weight: u32,
    /// 备胎标记（默认 false）：false = 活跃条目（正常参与加权轮询）；
    /// true = 备胎（活跃条目全部失败/熔断时才启用）——failover 主备语义，
    /// 平时全打主、主挂才切备
    #[serde(default)]
    pub standby: bool,
}

fn default_weight() -> u32 { 1 }
```

存储层 `store/docs.rs::custom_models_load/save` 为行文档表按字段存取，新增字段走 serde default，**存量数据零迁移**（旧行缺 weight 反序列化为 1）。

### 4.2 校验规则变更

`upsert` 的名称唯一性校验改为：

```rust
// 旧：canonical 冲突即拒绝
// 新：仅拒绝「同名 + 同 base_url + 同 api_key」完全重复——
//     同名不同上游 = 合法上游组成员；完全重复 = 无意义冗余
if let Some(dup) = list.iter().find(|e|
    e.id != m.id
    && canonical_id(&e.name) == canonical
    && e.base_url == m.base_url
    && e.api_key == m.api_key
) {
    return Err(format!("相同模型与上游地址/Key 的条目已存在：{}", dup.name));
}
```

同名（canonical 相同）但 base_url 或 api_key 不同 → 放行，构成上游组。

### 4.3 读取接口变更

```rust
/// 旧：find_enabled(data_dir, model) -> Option<CustomModel>（同 canonical 多条取首条）
/// 新：返回全部 enabled 条目（上游组）；单条语义调用方取 .first()
pub fn find_enabled_all(data_dir: &Path, model: &str) -> Vec<CustomModel>

/// 保留兼容包装（白名单预检 / catalog 等单条语义调用方零改动）：
pub fn find_enabled(data_dir, model) -> Option<CustomModel> {
    find_enabled_all(data_dir, model).into_iter().next()
}
```

调用方盘点（现状 4 处 + 命令层）：

| 调用方 | 改造 |
|---|---|
| `dispatch.rs::resolve_target` ⓪ 段 | P4 中整体移除（改入源集合），过渡期改用 `find_enabled_all` 判空 |
| `routes.rs` 三处 `TargetPool::Custom` 执行分支 | P2 改为接收 `Vec<CustomModel>`（组） |
| `routes.rs` 白名单预检 `find_enabled(...).is_some()` | 不改（存在性判断，语义不变） |
| `unified_catalog.rs` 源 3 聚合 | 改为按 canonical 分组合并（见 4.4） |
| `commands/api_server.rs::custom_model_test` | 不改（逐条探测，UI 每行独立测试按钮语义保留） |

### 4.4 目录聚合防重复

`unified_catalog.rs` 源 3：同 canonical 多条 custom 条目必须合并为**单行**（否则 `/v1/models` 出现重复模型名）：

- 倍率取组内最小（展示口径与 Smart 调度「倍率小者优先」一致）
- vendor / supports_image 取首条 enabled 条目
- 合并组内任一条 enabled 即整体可命中（`find_enabled_all` 已按 enabled 过滤，天然一致）

### 4.5 UI 变更

`src/components/api/CustomModelsPanel.tsx`：

1. 表单校验：移除「名称重复」前端拦截，仅提示「同名多条将组成上游组，负载均衡轮询」；保留「完全重复（同名+同地址+同 Key）」拦截。
2. 列表展示：同名多条按名称分组显示，组行标注「N 个上游」徽标；展开可见每条的 base_url / vendor / weight / enabled / 探活结果。
3. 表单新增 `weight` 输入（1-100，默认 1）与「备胎」开关（standby，默认关）；列表组行内每条标注「主 / 备」角色徽标。
4. `src/types.ts::CustomModel` 同步加 `weight: number`、`standby: boolean`。

### 4.6 测试与验收

测试（`custom_models.rs` tests 模块新增）：

- `t05_same_name_multi_upstream`：同名不同 base_url 两条 upsert 成功；`find_enabled_all` 返回 2 条；`find_enabled` 仍返回首条
- `t06_exact_duplicate_rejected`：同名同 base_url 同 api_key 拒绝；同名同 base_url 不同 api_key 放行

- `unified_catalog.rs`：同 canonical 两条 custom 聚合后目录单行、倍率取最小（扩展现有 t13/t14 风格用例）

## 🔧 5. P2 负载均衡：组内选路 + 粘性 + 重试轮换

### 5.1 新模块 `custom_lb.rs`

新增 `src-tauri/src/api_server/custom_lb.rs`（选路 + 轮换状态，纯函数为主便于测试）：

```rust
/// 组内选路：加权轮询（组内共享计数器），跳过熔断中的上游（P3 表查询）与
/// 已试条目；优先活跃条目（standby=false），活跃候选为空时才启用备胎。
/// 返回 None = 组内全部熔断/已试尽（交由调用方按错误矩阵处置）。
/// 策略收敛为唯一入口，后续 least-inflight/P2C 可插拔。
pub fn pick_upstream(
    group: &[CustomModel],
    tried: &HashSet<String>,          // 已试过的 cm.id（组内轮换排除）
    circuits: &CustomCircuits,        // P3 熔断表（P2 阶段传空实现）
    counter: &AtomicUsize,            // 组内共享轮询计数（挂在 ApiSharedState，
                                      //   键 = canonical 模型名——按模型各计各的，
                                      //   避免单全局计数器跨组交替破坏组内分布）
) -> Option<CustomModel>
```

选路算法（两步）：

```text
候选 = 组内 enabled - tried - 熔断中
活跃 = 候选中 standby=false；备胎 = 候选中 standby=true
① 活跃非空 → 活跃集按 weight 展开后取 counter % 展开长度
② 活跃为空 → 备胎集按 weight 轮询（同样算法）
③ 两集皆空 → None
// weight=0 视为 1；粘性命中且未熔断/未 tried 时优先返回粘住条目（跳过计数器）
```

粘性：

```rust
/// 会话粘同上游：键 = wb_sticky::SessionKey::from_body(body).cache_key()
/// 值 = cm.id；TTL 60s，内存态不落盘（与池粘性同口径）
```

存储位置：`ApiSharedState` 新增字段（`custom_upstream_sticky: Mutex<HashMap<String, (String, Instant)>>` + `custom_lb_counters: Mutex<HashMap<String /*canonical*/, AtomicUsize>>`——计数器**按模型分组各计各的**，不共享全局计数，避免多组并发时轮询分布互相干扰）。同请求池粘性并发竞争无害（最后写入胜出）。

### 5.2 执行路径改造（custom_route.rs）

`custom_stream_chat` / `custom_aggregate_chat` 签名变更：`cm: CustomModel` → `group: Vec<CustomModel>`。执行骨架：

```rust
let mut tried = HashSet::new();
let session_key = pool_session_key(body);   // 复用 dispatch::pool_session_key
let mut attempt = 0;
let max_attempts = group.len().min(3);      // 与 wb/qoder 轮换上限口径一致
let prepared_core = parse_body_once(&body_vec);   // loop 外解析一次

loop {
    let cm = pick_upstream(&group, &tried, &circuits, counter_for(&canonical))
        .expect("入口已确认组内有未熔断上游（pool_health 前置）");
    tried.insert(cm.id.clone());
    // 每次 attempt 按所选条目重建请求体（模型名对齐 cm.name 原文，见约束 5）
    let prepared = rebuild_body(&prepared_core, &cm);

    match execute_once(&cm, &prepared) {   // 现有单上游逻辑原样抽取
        Ok(()) => {
            clear_circuit(&cm.id);          // 成功即清熔断（P3）
            if let Some(sk) = &session_key { record_sticky_upstream(..., cm.id); }
            break;
        }
        Err(kind) => {
            note_circuit_failure(&cm.id, &kind);   // P3 记账
            attempt += 1;
            // SSE 铁律：sent_any 后就地收尾，不轮换
            if attempt >= max_attempts || sent_any { 收尾; break; }
            // 否则继续 loop 换下一上游
        }
    }
}
```

关键约束：

1. **`sent_any` 护栏**：`wb_sse::stream_forward` 需返回（或回调暴露）已发字节标志——流内错误在已产出内容后禁止换上游重试，直接收尾（对齐 wb/qoder 流路径既有护栏）。
2. **可轮换失败定义**（与 Qoder 空完成换号同口径）：连接错误 / 连接超时（3s）/ HTTP 5xx / 429 / 402 / 首字超时（10s 无首字节）/ 流内错误且 `!sent_any`。
3. **非可轮换**：`sent_any` 后任何失败。401/403 参与轮换（同名多上游 = 不同供应商，一条 Key 失效换另一条合理），但熔断记账按长窗处理（§6.2）。
4. **快速失败参数（custom 专用 agent）**：现有执行路径复用 `wb_upstream::wb_agent()`（连接 10s / 空闲读 300s）——连接 10s 对快速失败太长。custom 路径改用**专用 agent：连接超时 3s、首字超时 10s（现状保持）、空闲读 300s**；连接拒绝/3s 连接超时立即进入组内轮换。
5. **请求体按条目重建**：`prep_body` 不能只做一次——模型名必须对齐**所选条目自身的 name 原文**（同名组内各条目 canonical 相同但原文大小写/空白可能不同，如 `GLM-5.3` 与 `glm-5.3`，部分上游对模型名大小写敏感）。loop 外解析 body 一次，每次 attempt 内仅覆写 `v["model"] = cm.name` 后序列化。
6. **用量记账**：`record_usage_custom` 保持 model 维度不变；每次 attempt 各记一条（成功/失败如实落账）。`logger.log_request` 的 `acct_name` 参数由 `cm.name` 改为 `format!("{}#{}", cm.name, &cm.id[3..7])`（前 4 位区分同组多条，日志可读性）。
7. **TOCTOU 说明**：`pick_upstream` 的熔断表判定与实际执行之间存在竞态（选路时未熔断、执行时刚过期）——无碍，熔断表是优化而非正确性保证，多打一次故障上游由组内轮换兜底；不做加锁串行化。

### 5.3 测试与验收

测试（`custom_lb.rs` tests + `custom_route.rs` 既有测试扩展）：

- 加权轮询分布：weight=3/1 两上游，10 次选路命中比 ≈ 3:1
- 组间隔离：两组各自独立计数，A 组的轮询不影响 B 组分布（per-model counter）
- 主备：活跃条目存在时备胎永不命中；活跃全失败/全熔断 → 备胎接管；活跃恢复 → 回流活跃
- 排除重试：tried 含首条 → 选路必返回第二条
- 全熔断/全 tried → None
- 粘性：同 session_key 粘同上游；粘住的上游进入 tried/熔断后重选
- 轮换：mock 上游一条 401、一条 200 → 客户端收到 200（首次失败换上游无感）

**验收标准**：双上游轮流命中（加权）；一条 401 时请求自动落到另一条且客户端无感；`sent_any` 后失败不再轮换；`cargo test` 全绿。

## 🔧 6. P3 熔断：实例级渐进冷却

### 6.1 状态表

新增（`custom_lb.rs` 内，完全镜像 `qoder_route.rs::QODER_MODEL_COOLDOWNS` 模式）：

```rust
/// 键 = cm.id（同名多上游各自独立熔断，不是 name）
/// 值 = (冷却截止时刻, 连续失败片段数)；成功即清；重启清零
static CUSTOM_UPSTREAM_CIRCUITS: OnceLock<Mutex<HashMap<String, (Instant, u32)>>>
```

接口：

```rust
pub fn circuit_open(cm_id: &str) -> bool                  // 未到期 = 熔断中
pub fn note_circuit_failure(cm_id: &str, kind: FailKind)  // 按类记账
pub fn clear_circuit(cm_id: &str)                         // 成功即清
pub fn circuit_remaining_secs(cm_id: &str) -> Option<u64> // 池状态/错误矩阵用
pub fn circuit_snapshot() -> Vec<(String, u32, u64)>      // 池状态接口导出
```

### 6.2 渐进冷却参数（沿用 Qoder 口径，写死）

| 项 | 值 | 说明 |
|---|---|---|
| 基窗 | 30s | `SERVER_COOLDOWN_BASE_SECS` 同值 |
| 递增 | ×2 / 失败片段 | 30→60→120→240→480 |
| 封顶 | 480s | 8 分钟 |
| 递增条件 | **既有窗口已过期**才 +1 片段 | 防单请求组内轮换把窗口推满（Qoder 审查修复同款：换号不递增计数） |
| 半开 | 窗口到期后下一请求自然放行 | 无探测线程；放行请求失败 → 新片段重新记账 |
| 401/403/402 长窗 | 600s | 配置/账户错误（Key 失效、欠费、额度耗尽）恢复慢；参与组内轮换但不吃渐进表，直接落 600s |
| 429 | 不解析 Retry-After | 统一走渐进表（30s 起）；上游限流场景渐进窗口已够用 |

**半开恢复语义（custom 组相比 Qoder 单源场景的天然优势）**：冷却到期后下一请求自然放行探测——探测请求若失败，执行路径的组内轮换立即兜底切换到其他未熔断上游（`!sent_any` 阶段），**客户端无感**，无需独立探测请求或恢复队列；探测成功 → `clear_circuit`，该上游重新参与加权轮询。恢复探测的真实成本仅是「一次可能落在故障上游的请求多了一次组内换路」，已被快速失败参数（连接 3s）压到最低。

### 6.3 错误矩阵衔接

- 组内全熔断 + 单源（无同名 trae/buddy/qoder 源）→ `DispatchError::NoHealthy(TargetPool::Custom)`。`routes.rs` 现把 Custom 池错误统一映射为 "no healthy account available"（协议错误映射处 `TargetPool::Custom => ...`），需细化为携带剩余冷却秒数的 503（对齐 ModelCooling 的 429 口径选一：**维持 503 no healthy**，与三池耗尽语义一致，客户端兼容）。
- 池状态接口：`pool_status` / ResourceSummary 数据源追加 custom 组每上游 `fails / cooling_secs / weight / enabled`，UI 徽标复用 `PoolHealthBadges` 风格新增「熔断中」态。

### 6.4 测试与验收

测试：

- 连续 3 次失败 → `circuit_open == true`，选路跳过该上游
- 窗口过期（手动拨 Instant）→ 放行；再失败 → 片段 +1、窗口翻倍
- 窗口未过期内的多次记账（同请求轮换）→ 计数不递增（防放大）
- 成功 → `clear_circuit`，`circuit_open == false`
- 401 → 直接 600s 窗，不吃渐进表

测试隔离备忘：熔断表为 `static OnceLock`（进程级共享），测试间会串扰——用例统一以唯一 cm.id（测试内随机生成）为键隔离，或用例开头 `clear_circuit` 清场（对齐 qoder_route 测试直接操作 cooldown_map 的既有做法）。

**验收标准**：连续失败后该上游进入冷却、选路跳过；冷却过期单次成功即清除；401/403 落 600s 长窗。

### 7.3 语义变化说明（评审重点）

| 场景 | 改造前 | 改造后（v3） |
|---|---|---|

4. **单条上游组退化**：组大小 = 1 时 P2 轮换空转（pick 唯一一条）、P3 熔断语义退化为「冷却期内报 503」（与现状「失败直返」差异：冷却期内快速失败不再硬打上游——行为增强，非破坏）。
5. **主备退化**：全组无 standby 标记 = 纯加权轮询（默认行为不变）；单活跃 + 单备 = 标准主备 failover；多活跃多备自然组合（活跃间轮询、备胎间轮询）。
6. **同上游多 Key 分摊限流**：同名同 base_url 不同 api_key 的多条记录（§4.2 校验放行的自然结果）= 组内多 Key 轮询，可缓解单 Key 限流；任一 Key 401/403 仅该条落长窗，其余 Key 继续服务。
7. **`custom_model_test` 命令契约不变**（逐条探测）。
8. **AGENT.md 契约同步**：实施合入时更新 §5 custom 命令表（weight/standby 字段）、api_server 模块注释与 §6 落池规则（custom 入调度链、`custom/` 前缀）。

## 📌 11. 决策点

**已拍板（v3，2026-10-14）**：

| # | 决策 | 结论 |
|---|---|---|
| A | 同名时 custom 是否默认优先 | **不默认优先**——custom 普通池按调度规则走，默认候选序尾部兜底；显式指定走 custom 用 `custom/` 前缀 / Key 绑定 / per_model |
| B | `custom/` 前缀锁池 | **采纳**——`TargetPool::parse` 扩展 `"custom"`，单池候选语义与其他池前缀一致 |
| C | API Key 绑定池 | **扩为五选项**「全局 / Trae / Buddy / Qoder / 自定义」，绑定 custom = 优先 + 不可用回退 |
| D | Key 绑定 / per_model / Smart vs custom | **显式配置全量生效**（⓪ 短路移除后统一走调度链） |

## 1. 简介

AI Work 助手是**浏览器直访**的多账号签到与 AI 资源调度一站式工作台，深度支持 **Trae / WorkBuddy（CodeBuddy）** 双账号体系：多账号 OAuth/凭证管理、每日自动签到、积分看板、JWT 自动续期，内嵌 **OpenAI / Anthropic / Codex Responses 三协议兼容 API 网关**。单进程 Rust axum 服务承载管理面 + 网关 + 调度器，Docker 一键部署，任意设备浏览器访问。

**核心功能**：

- 多账号管理：OAuth 登录（Trae 粘贴回调 / WorkBuddy 扫码轮询）、手动录入、分组、导入导出
- 一键签到：批量签到、失败自动重试、近 N 天趋势
- 积分看板：Trae 三线趋势 + WorkBuddy 积分/官方用量/本地 Token 统计
- API 网关：三池调度（Trae / WorkBuddy / 自定义模型）、会话粘性、ck_ 子 Key
- 内置调度器：每日 6 任务全自动（JWT 续期、双端签到、token 续期、积分快照）
- 通知渠道：Bark / Server酱 / 通用 Webhook
- 数据全部存服务端本地 SQLite，出网仅 Trae/腾讯上游，不上传任何服务器

## 2. 部署与登录

```bash
docker compose up -d --build
# 等待 healthy 后获取管理令牌
docker compose exec aiwork-server cat /app/data/conf/admin_token
# 浏览器访问 http://<服务器IP>:8080，粘贴令牌登录
```

环境变量、TLS 反向代理、备份恢复、桌面版数据迁移详见 **[server-deploy.md](server-deploy.md)**。

> ⚠️ `conf/vault_key.bin` 是账号凭据加密密钥，**丢失即全部凭据不可解密**，务必纳入备份。

登录会话有效期 7 天（HttpOnly Cookie），过期后自动跳回登录页。除主令牌外，可在系统设置页签发**附加管理员令牌**（最多 20 个，可单独吊销，明文仅创建时展示一次），适合多人共用管理面时按人分发。

## 4. 账号管理

### 4.1 添加 Trae 账号（OAuth 粘贴回调）

1. 点击「OAuth 登录」→ 复制登录链接，在**任意设备**浏览器打开并完成 Trae 登录；
2. 登录成功后浏览器跳转 `http://127.0.0.1:17388/authorize?...` 并停在「无法连接」页——**这是预期现象**；
3. 复制浏览器地址栏完整 URL，粘贴回 Web UI 提交；
4. 系统自动解析 JWT 与用户信息，账号入池。

> OAuth 登录的账号自带 refresh_token，支持 48h 懒续期与每日自动续期（调度任务）。

### 4.2 添加 WorkBuddy 账号（authUrl 轮询）

Buddy 账号页发起 OAuth → 按提示在浏览器打开 authUrl 完成授权 → 服务端自动轮询收取 token（≤300s）并入池，**无需粘贴**。

### 4.3 手动录入与导入导出

- **手动添加**：输入名称 + 粘贴 JWT（`eyJ` 开头），系统自动解析 user ID，可选分组；
- **导入**：支持桌面版导出的 JSON（按 uid 去重、分组合并）；导入前可预览解析结果与重复标记；
- **导出**：下载 JSON（含凭据，注意妥善保管，用后即删）。

### 4.4 账号操作

| 操作 | 说明 |
|------|------|
| 编辑 | 修改账号名称 / JWT |
| 删除 | 移出账号池 |
| 查看/复制 JWT | 列表 JWT 已掩码（前4+****+后4），完整值按需获取 |
| 刷新 JWT | 自动续期（需 refresh_token；临期 48h 内才真正发起网络请求） |
| 清除冷却 | 立即解除签到错误冷却 |
| 积分刷新 | 查询剩余积分与过期时间 |

### 4.5 分组管理

创建分组（自定义颜色）、账号移动分组、删除分组时组内账号回落「未分组」。签到与网关池均可按分组筛选。

## 5. 一键签到

### 5.1 签到范围与选项

| 选项 | 说明 |
|------|------|
| 全部账号 / 按分组 / 手动勾选 | 签到范围 |
| 跳过已签到 | 当日已签自动跳过 |
| 跳过已过期 | JWT 已过期自动跳过 |

点击「开始签到」后，进度经 WebSocket 实时逐账号推送（连接不可用时自动回退 SSE，均无需刷新页面）。失败自动重试最多 2 轮（30s / 90s）。

### 5.2 签到状态与错误冷却

| 状态 | 说明 |
|------|------|
| 成功 | 显示获得积分 |
| 已签到 | 当日已签，跳过 |
| 失败 | 显示错误信息 |
| 冷却中 | 处于错误冷却期，自动跳过 |

| 错误类型 | 冷却时长 |
|---------|---------|
| PlanLimit（额度不足） | 12 小时 |
| SoftRate（频控） | 60 秒 |
| SessionDead（JWT 失效） | 需重新 OAuth |
| Server / Client | 10 分钟（累计触发） |

签到成功后自动清除冷却；也可在账号管理手动清除。

### 5.3 WorkBuddy 成长中心

Buddy 签到页可开启成长中心自动化：旅行 / 盲盒 / 任务领奖，随签到流程链式执行，各步独立容错。

## 6. 积分看板

### 6.1 Trae 积分

- **排行**：各账号积分总量 / 今日获得 / 过期时间；
- **三线趋势**：近 30 天总数线 / 获得线 / 消耗线（数据源为每日快照，调度任务 23:40 自动采集）；
- **明细**：单账号积分明细（签到/消耗/积分包来源）。

### 6.2 WorkBuddy 积分与用量

- **积分三件套**：余额 / 已用 / 容量（10 分钟缓存）；
- **官方请求用量**：今日 / 近 7 天 / 本月 + 逐日按模型聚合（官方接口 31 天分页），积分消耗趋势支持 7/30 日切换；
- **本地 Token 统计**：合并本机 projects JSONL 的 usage（缓存命中率 / 模型分布 / 热力图）；
- **快照回退**：官方用量不可用时自动切换本地余额时序差分口径（页面明示「快照回退」）。

## 7. API 网关

网关随服务**常驻运行**（无需启停），默认端口同管理面 8080（`/v1/*`）。全部网关配置在「API 服务」页维护。

### 7.1 三池调度

| 池 | 上游 | 说明 |
|---|---|---|
| Trae | SOLO 上游 | 消耗通用积分（product_id 208） |
| WorkBuddy | copilot.tencent.com / www.workbuddy.ai | 消耗 Buddy 积分；按账号区域自动路由 |
| 自定义 | 任意 OpenAI 兼容上游 | 模型命中即直达，不参与池间策略 |

**池间策略**：`smart`（默认：积分到期优先 → 模型倍率 → 健康积分和）/ `priority`（严格按序）；支持 `per_model` 模型级覆盖与跨池回退开关。

**账号池**：勾选参与调度的账号、选择池内策略（临期优先 / 积分多优先 / 随机 / weighted / p2c）；调度自动跳过禁用 / 冷却 / 积分过期账号，单账号额度耗尽自动换号。

### 7.2 API Keys

- **ck_ 子 Key**：与上游真实凭证分离；支持每日限额、`allowed_accounts` 上游账号白名单、`schedule_mode`（临期优先 / 专一固定账号）；
- 未配置任何启用 Key 时**全拒（fail-closed）**；
- 鉴权头：`Authorization: Bearer <key>` 或 `x-api-key: <key>`。

### 7.3 模型目录

- **统一目录**：Trae 官网同步 + WB 目录 + 自定义模型三源合并，元数据四层兜底（人工覆盖 → 官网 → 默认 → 系列推断）；
- **人工维护**：行内编辑展示名 / 倍率 / 思考档位 / 上下文 / 图片支持，已人工维护条目标 `*`，可一键清除恢复自动来源；
- **四段模型路由**：别名 / 通配 / 系列（claude-*→glm-5.3、gpt-*→deepseek-v4-pro 等）/ `-thinking` 后缀注入深度思考。

### 7.4 使用示例

```python
from openai import OpenAI

client = OpenAI(
    api_key="ck_xxx",
    base_url="http://<服务器IP>:8080/v1"
)
response = client.chat.completions.create(
    model="glm-5.3",
    messages=[{"role": "user", "content": "Hello!"}],
    stream=True
)
```

**支持端点**：`POST /v1/chat/completions`、`POST /v1/completions`、`POST /v1/messages`（Anthropic，Claude Code 直连）、`POST /v1/responses`（Codex，仅 WB 上游）、`POST /v1/images/generations|edits`、`GET /v1/models`、`GET /status`、`GET /health`。

### 7.5 用量统计

按日请求统计（7/14/30 天窗口），Trae / Buddy / 自定义三池分库查询，另附**近 30 天三池请求堆叠柱状图**；模型分布 Top 5，请求日志（含 TTFB）可查详情。

## 8. 调度器与通知

### 8.1 内置调度器（每日 6 任务，全自动）

| 任务 | 触发时刻 | 说明 |
|---|---|---|
| Trae JWT 自动续期 | 05:30 | 临期 48h 内自动续期，保住凭据生命线 |
| Trae 每日签到 | 09:00 | 全账号签到领积分 |
| WorkBuddy 每日签到 | 09:10 | 签到 + 成长中心（跟随「自动补签」开关） |
| WB token 兜底续期 | 10:30 | 到期前 24h 懒刷新 |
| WB 积分快照 | 23:30 | 补齐近 7 日消耗差分时序 |
| Trae 积分快照 | 23:40 | 同上 |

- 触发语义：今天已过触发时刻 && 今天未跑；**服务重启后自动补跑**当天错过的任务；
- 失败 30 分钟冷却后自动重试；
- 各任务最近执行情况在概览页 / 设置页「调度器」卡查看；
- 高级：`docker compose exec aiwork-server /app/aiwork-server --task-run <name>` 可手动兜底单任务。

### 8.2 通知渠道（设置页）

支持 **Bark / Server酱 / 通用 Webhook** 三渠道推送：

- 触发事件：**签到完成**（调度签到任务 + 手动签到）、**调度任务失败**；
- 各渠道独立开关与地址配置，「发送测试」按钮即时验证（不落盘）；
- 总开关默认关闭；单渠道失败仅记日志，不影响主流程。

## 9. 运行日志

日志页支持按类型（签到 / 网关 / 应用）、日期、关键词查询：

## 11. 常见问题

### Q: 浏览器打开 OAuth 回调地址显示「无法连接」？

**A**: 这是**预期现象**。Web 版不监听本机 17388 端口，登录完成后浏览器停在错误页——复制地址栏完整 URL 粘贴回 Web UI 即可完成录入。

### Q: 容器重建后账号全部报解密失败？

**A**: `conf/vault_key.bin` 丢失或 `AIWORK_VAULT_KEY` 与历史不一致。恢复备份的 volume 或固定相同 env；密钥无法找回时账号只能重新录入。

### Q: 登录提示 token 无效 / 频繁跳回登录页？

**A**: 令牌取自 `conf/admin_token` 或 `AIWORK_ADMIN_TOKEN` env；env 变更后需重建容器。会话 Cookie 有效期 7 天，过期自动跳登录页属正常。

### Q: 手动签到没有实时进度？

**A**: 实时进度走 WebSocket（`/api/ws`），连接失败时前端自动回退 SSE。反向代理需支持 WS 升级头（Nginx `proxy_set_header Upgrade` + `Connection "upgrade"`）并对 SSE 禁缓冲（`proxy_buffering off` + `proxy_read_timeout 3600s`，见 server-deploy.md TLS 示例）。

### Q: 定时任务没跑 / 签到时间不对？

**A**: 任务由服务端内置调度器托管（见 §8.1），重启后自动补跑；确认容器 `TZ=Asia/Shanghai` 未被覆盖。

### Q: JWT 过期了怎么办？

**A**: OAuth 录入的账号有 refresh_token：每日 05:30 调度任务自动续期，也可在账号管理手动「刷新 JWT」。若 refresh_token 被服务端吊销（账号在别处重新登录、IDE 内退出等），需重新走 OAuth 录入。

### Q: API 服务返回 401？

**A**: 检查 `ck_` Key 是否正确且启用（fail-closed，未配置 Key 全拒）；检查账号池是否有可用账号（未冷却、有积分）；查看网关请求日志定位。

### Q: 签到失败提示「额度不足」？

**A**: 账号积分耗尽（网关消耗与签到获取同一积分池）。该账号自动进入 12 小时冷却，次日签到补分后自动恢复。

### Q: 数据存储在哪里？如何备份？

**A**: 全部在容器 volume `./data:/app/data`：`data/aiwork.sqlite`（业务库）+ `conf/`（token 与密钥）。备份 `data/` 目录即可（见 server-deploy.md 备份章节）。
